# Domain documentation

Dots uses a single project vocabulary. Before exploring a feature, read the root `GLOSSARY.md` if it exists and the relevant [architecture decisions](../decisions/README.md).

Use the project’s terms in issues, proposals, tests, and code reviews. When a term needs clarification, use domain-modeling to resolve it. Create or extend `GLOSSARY.md` when a definition is agreed.

Record material architecture decisions in `docs/decisions/` using the linked guide. If a proposal conflicts with a recorded decision, cite the decision by filename and explain what warrants revisiting it. Record an accepted replacement as a superseding decision.
