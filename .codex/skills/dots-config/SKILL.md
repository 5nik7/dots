# Dots Configuration Integration

Read [profile configuration](../../../docs/profiles.md), [data contracts](../../../docs/specification.md) and [configuration safety](../../../docs/safety.md). Follow the [command review](../../../agents/guides/commands.md#configuration-integration-review): every new or changed command records add, update, or no configuration integration change needed, with a reason. A review does not require inventing a new setting.

Trace the setting from its declared default through storage, resolution and its actual consumer before editing. Record the owner, key/type/default, precedence, supported platforms/consumers and activation behavior in the focused plan or change notes. Keep durable definitions in the existing schema/catalog and canonical docs, not a new tracking registry. Use [profile maintenance](../dots-profile-maintenance/SKILL.md) for manifests/environment and [file maintenance](../dots-files-maintenance/SKILL.md) for catalog mappings. Native application settings, theme palettes and file/Git colors retain their existing owners unless an explicit integration is being designed.

`profile_config.py` and `config_cli.py` own saved configuration and guarded edits; `config_menu.py` shares those plans for popup drafts. Visual declarations live in `default/{icons,colors}.toml` and profile overrides. `style_config.py` resolves defaults, parents, then the selected profile, applying general values before app overrides within each layer. Preserve fieldwise inheritance, empty icons, false attributes and the canonical Codex icon's compatibility alias. `style_catalog.py` identifies supported bindings; expose a control only after wiring and verifying its consumer.

Get resolves recognized keys through effective layers and returns null when absent; unknown keys remain errors. Explain adds provenance and consumer/activation details. Update validation, completion, browser details and canonical docs together. `config_refresh.py` coordinates visual saves and explicit refresh through Store; `theme_styles.py` supplies projections. Preserve the selected palette, inactive-profile behavior, no-op saves, dry-run purity and `--no-refresh`. Publication failures retain the previous generation; consumer failures retain the save and report retryable activation. Nonvisual settings retain their separate reload/install rules. Reading configuration must never publish, run hooks or activate consumers.

Verify in owned roots with `tools/test_profile_config.py`, `tools/test_style_config.py`, `tools/test_config_live.py` and affected `tools/test_config_menu.py` cases. Add the actual consumer's checks when changing a binding: prove values reach its output, not just the saved file. Cover inheritance/reset, unsupported existing entries, literal safety, stale inputs, rollback/undo, inactive/no-op changes, failure reporting and exact scalar/JSON output. Follow [command maintenance](../dots-command-maintenance/SKILL.md) for both frontends and menu assessment, then [documentation maintenance](../dots-documentation-maintenance/SKILL.md) for sources and wiki. Record native evidence separately from fixtures.

Typed behavior/formatting and shell settings live in `default/config.json` and `profiles/NAME/config.json`; profile manifests retain structural data. Unqualified preference saves and browser edits target shared defaults; explicit `--profile NAME` retains profile overrides. Native application files remain authoritative. Use `config_values.py` for literal bracket keys, types, null reset and fieldwise resolution. Review fg/bg/attributes for icons and adjacent spans, labels and values, tabs/tab stops, indentation, spacing, padding, alignment and native row/side/section placement. Add future formatting controls only after wiring their consumer, with isolated checks and CLI/popup/completion/docs coverage. Do not advertise unused fields.

`formatting.apps.menu.popup` and `colors.apps.menu.popup` own Dots popup placement, frame and colors independently of ordinary shell FZF defaults. The shared selector/native host read these controls on invocation; popup-only saves must report next-popup activation without requiring theme publication or a server reload. Verify inheritance, plain rendering, inline fallback and exact-client ownership through `tools/test_menu_popup_config.py` when changing this projection.

Expose finite choices and custom syntax through `config_values.constraints`, keeping validation, `config explain`, Config details/editors and `config-value` completion consistent. Do not put possible values into scalar get output. Popup width/height use the shared `auto`/`fit`/`fill`, percentage or integer sizing contract; preserve exact-client bounds, preview selection space and inline-platform limits.

Shared CLI/menu key columns use the existing `formatting.apps.{cli,menu}.label_width`, `label_gap` and `alignment`: widths accept cells, percentages or zero for spacing only. Reuse `row_layout.py` and the Bash helper instead of adding local padding controls. Formatting-only saves activate on the next invocation/popup. Keep key discovery independent of mutation imports and test fresh completion processes with optional native weather present or malformed; in-process tests can hide import-path failures. Run `tools/test_config_alignment.py` for the shared consumer checks.

Use [dots-config-audit](../dots-config-audit/SKILL.md) when repository-wide discovery is requested; its static findings require owner/consumer review and do not authorize extra implementation. Wttr keeps its active native TOML via `config_wttr.py`; FZF keeps a protected popup projection; the nested Neovim bridge uses bounded JSON/public Anodize APIs. Preserve owned picker actions, native file comments, selected theme, last-good consumers and inactive-profile boundaries.

Key-only interactive `config set KEY` enters the same `config_menu.edit` draft/review path directly, including native keys and `--no-refresh`. Keep JSON/dry-run/noninteractive omissions as errors and return after Save/cancel. Color choices read the active palette as data: retain semantic role references, store native entries as `palette.NAME`, and preserve global `colors.ROLE.fg`/`.bg` references. Validate reference cycles and explain missing-native-name fallback. Reuse this entry point rather than duplicating picker validation or write logic; `tools/test_config_menu.py` covers direct editor and private terminal behavior.

Canonical public paths and compatibility aliases are centralized in `config_keys.py`. Feature styles use `colors.apps.{todo,fonts,wiki,menu,pkgs}`; typed popup/menu-entry colors and FZF/Neovim appearance live in the reserved `[controls]` sections of adjacent color/icon TOML files. Smart-endpoint browsing and full-key/branch completion use `config_completion.py`; plain Tab lists full keys, while `..` requests immediate branches with a blank FZF query. Keep literal bracket keys and typed values consistent across native adapters. Human color/icon samples use selected-profile resolution, exact styles and explicit provenance without changing data interfaces. Glyph editors return cached selections without clipboard, download or execution effects. Key migration uses `config_migration.KeyPlan` and retained Store operations; compare affected consumer values before offering `migrate --keys`, preserve comments, reject conflicting aliases and verify repeat no-op/undo. Run `tools/test_config_browsing.py`, `tools/test_config_discovery.py`, `tools/test_config_completion.py` and the generated `tools/test_config_layout.py` consumer checks for this contract.

Use `preference_files.py` for composition, actual-file provenance and the literal TOML typed-control section; preserve it during ordinary style edits. `config_transfer.py` owns reversible `migrate --layout` and source-wins portable appearance imports. Import excludes structural data, native files, settings and nonappearance application controls. Cover default/profile destinations, repeat, stale guards and undo with `tools/test_preference_files.py`; cache invalidation must include missing-file creation through parent-directory guards.
