# Dots Todo Maintenance

Resolve the intended Dots checkout before editing. Outside Dots, use this skill's resolved source location or `dots files show dots:todo-maintenance-skill --json` to find its source checkout; do not assume the current project owns Todo's implementation. Follow an explicitly requested checkout, inspect its Git state and read its `AGENTS.md`.

Read the [Todo maintenance guide](../../../agents/guides/todo.md) in that checkout for component ownership and focused checks. When reading an installed link or copy, resolve guide links against the source checkout. Use [Todo documentation](../../../docs/todo.md) for current behavior and the [focused plan](../../../plans/todo.md) for accepted scope and verification limits.

Keep scope discovery, stable UUIDs, guarded goal transactions and literal native arguments intact. Use shared presentation, selector, popup/context and input helpers. Briefs, clipboard exports and Codex submissions must retain full goal/subgoal notes and criteria. Validate actual Plan Mode and busy-thread behavior separately from prompt wording.

Select tests for the changed component using owned homes, goal stores, tmux clients and Codex fixtures. Never use the user's live goals, clipboard, conversations or service as an automated fixture. Preserve Bash/native PowerShell behavior and report unavailable native evidence explicitly.

For new routes or changed command contracts, follow the command guide and record the menu assessment. Update canonical docs and regenerate/check the local wiki when available. Source edits do not authorize unrelated installs, service restarts, commits or publication; carry out activation already authorized for the current task through its existing managed workflow.
