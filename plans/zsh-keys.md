# Personal Zsh keybindings

Status: implemented and verified locally; native Linux/WSL and personal keyboard acceptance remain pending.

## Accepted behavior

Centralize personal vi-mode settings, cursor handling, Backspace, clipboard and history bindings in `shells/zsh/keys.zsh`. Retain platform commands and plugin loading in the Termux hook and history persistence in `options.zsh`. Use case-insensitive contiguous substring matching, unique results and dynamic Dots selection/error colors. Preserve FZF Ctrl-R and Tab completion. Follow the [presentation gate](README.md#presentation-gate-for-every-plan), using native ZLE colors and readable missing-theme fallbacks.

Load preferences before plugins, apply bindings after widget registration, and use deduplicated vi-mode after-init/after-lazy/after-selection callbacks. Keep native cursor fallback additive and leave the plugin's cursor widgets intact. New-shell activation is required for the initial migration; later `rl` calls reload settings without resetting the maps. No plugin installation/update, live-shell reload, commits or pushes are included. Existing Yazi/Codex work and unrelated configuration edits remain intact.

This is personal Zsh behavior on Termux/Linux/WSL. Bash and native PowerShell editing are unchanged, including Windows app destinations and the integration-only hook. Native Linux/WSL keyboard acceptance is pending; Termux PTY fixtures do not establish it. No new public CLI/schema is introduced. The browser's Zsh parser now recognizes `bindkey -a`, emitted by Zsh for `vicmd`, so live normal-mode bindings are visible.
